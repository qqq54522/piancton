# 卖点智库 UX/UI 设计规范

状态：当前执行文档  
更新时间：2026-09-13
事实来源：[`IMAGE_SEARCH_REBUILD_MASTER_PLAN.md`](./IMAGE_SEARCH_REBUILD_MASTER_PLAN.md)

本文档约束产品界面的信息层级、交互与视觉表达。业务模型、搜索链路和阶段状态仍以改造总纲为唯一事实来源。

正式产品名称为“卖点智库”。`piancton` 只作为仓库、服务和数据库等内部技术标识，不出现在用户界面的品牌位置。
顶部品牌、首页主标题、登录页和浏览器标题必须统一使用“卖点智库”；首页不得再显示旧名称“业务素材库”。

## 1. 产品体验目标

界面应让业务人员和设计师感到这是一个安静、专业、可信赖的素材运营台，而不是数据库管理器或 AI 参数面板。

每个页面优先回答三件事：

1. 我现在在哪里。
2. 当前最重要的任务是什么。
3. 完成任务后系统会发生什么。

## 2. 角色主任务

- 业务用户：用一句自然语言找到可用素材，必要时按体系缩小范围，选择尺寸并下载。
- 设计师：上传已审核主图，维护版本、卖点关系和素材独有搜索话术，并向业务用户发布产品公告。
- 管理员：治理用户权限、搜索问题、AI 待审核关系、素材缺口和审计记录。

不同角色共享同一套视觉系统，但首页操作与后台导航按权限展示，不把无权操作显示成不可用按钮。

## 3. 信息架构原则

### 3.1 一个页面只有一个主任务

- 首页只有一个搜索框，不再同时出现“业务搜索”和“本地图片搜索”。
- 上传窗口的主任务是发布图片；业务信息均为可选增强。
- 素材详情负责后续维护，不把所有关系、版本和话术塞进首次上传。
- “相关素材”只承载其他素材组；当前素材组的延展尺寸和历史版本只在“版本与尺寸”展示，不能在页面上重复成两种对象。
- 后台页面先显示任务标题和用途，再显示筛选、表单或数据列表。

### 3.2 渐进披露

- 首次上传只强制图片文件。
- 首次搜索话术建议录入 0～5 条，用于控制表单长度，不是数据库总上限。
- 选择主要表达卖点后，展示已继承公共话术的数量和少量示例，不把全部公共词铺满上传弹窗。
- 完整公共话术与短辅助关键词分开统计和展示；辅助关键词默认折叠，避免把“教材”“章节”一类索引词误当成业务人员可直接复用的话术。
- 公共话术为空时，管理员可以就地补充或进入卖点管理页；其他角色不因公共话术为空而无法上传。
- 发布后可以在素材详情根据真实反馈维护素材独有话术，建议保持 3～8 条并及时合并重复说法。
- 通用业务话术维护在业务概念层，素材层不重复填写。

### 3.3 六大体系不是导航树

- 上传时选择的是具体业务卖点，不是一级体系。
- 概念通过多对多关系关联体系，不把图片锁进唯一体系。
- 六大体系只作为搜索快捷筛选；用户未选择时保持跨体系召回。

### 3.4 新用户首次引导

- 新注册的业务账号首次登录后，用一次站内欢迎弹窗说明右侧洋葱专属 Agent、手动渠道浏览和连续对话找图；完成状态跟随账号，不依赖浏览器本地存储。
- 三张引导卡片分别展示：如何先问六体系并追问同步课与培优课；如何按渠道目录浏览，或直接让 Agent 找新疆合作案例图；需要语义判断时如何先问拍题精学涉及哪些卖点，再接着找这些卖点的图片。例子是帮助上手的方式，不是 Agent 必须遵循的步骤。
- Agent 可结合洋葱知识与当前已发布素材回答或找图；图片卡须经过本地真实素材核对。重点词和提问句用高对比色与字重帮助用户快速扫读，不显示已移除的顶部搜索框。
- 同一 Agent 会话里，手动输入和推荐问题复用同一个火山 AI Search `session_id`；“它、这个、刚才提到的卖点”等追问不能因为输入方式不同切断会话。刷新和换设备继续读取该用户已保存的对话；点击“新对话”开启新会话，不在自然日午夜清空。
- 从素材库“发送到 Agent”的图片显示为下一条消息的待发送附件。素材卡再发一张不同图片时，待发送图库图片自动切换为最新这张，不把旧待发图累加。成功问答后从顶部待发送区移除，并在用户提问消息中保留缩略附件；临时上传的图片也在这条消息保留文件名附件。用户可继续发另一张图提问，或自然追问本会话前面发过的图片；此前的图片名称、顺序及已有回答供同一火山会话回指，不反复占用顶部空间或自动重发旧图像素。失败时保留待发送图片供重试，无法确认旧图画面时如实说明。
- Agent 不展示未经火山平台提供的记忆百分比、进度环或虚构的上下文上限。Piancton 不拼接并按固定条数/字数裁剪历史；会话实际可用上下文由火山 AI Search 处理，不能向用户承诺无限模型窗口。
- 欢迎弹窗提醒右上角个人头像可打开喜欢、收藏、消息、反馈与更换头像。注册页可选六个预设头像或自己的图片；旧账号显示稳定的姓名首字头像。自定义头像只存入该账号的私有 `account-avatars` 路径，不进入素材图库。
- 存量用户在迁移时视为已完成，不因功能上线被强制重新阅读；设计师和管理员不展示以业务收藏流程为主的新手弹窗。
- 引导只说明现有任务入口，不得新增第二个搜索框、内部算法模式或必须完成的业务配置。

### 3.5 业务用户每日反馈

- 业务账号从注册次日起，在北京时间每个自然日第一次进入产品时显示一次“昨日使用反馈”；完成状态跟随账号，不能只存在浏览器本地。
- 反馈弹窗直接嵌入独立飞书表单。弹窗不能通过右上角关闭、Escape 或点击背景跳过；用户提交表单后点击“我已提交，完成今日反馈”才结束当天流程。保存失败时保持弹窗并给出明确错误。
- 新人欢迎弹窗优先于每日反馈；新账号注册当天、设计师和管理员不显示。原账号菜单中的“提交反馈”继续作为用户主动反馈入口，两个表单用途和状态相互独立。
- 飞书表单是跨域页面，前端不能把 iframe 加载完成当成提交成功；界面必须明确要求用户提交后手动确认。

### 3.6 站内公告与我的信息

- 设计师和管理员从左侧“公告管理”发布产品更新、功能优化和重要提醒；发布表单必须明确“发布后立即对全部业务用户生效”。
- 业务用户从头像菜单进入“我的信息”，信息页按时间倒序展示公告标题、正文、发布时间和发布人；没有公告、加载失败和加载中必须有独立状态。
- 头像右下角只在有未读公告时显示红色圆形数字，数字属于当前账号且上限显示为 `99+`；菜单内“我的信息”同步显示未读数量。
- 打开“我的信息”后自动把这次页面实际加载到的最新公告标为已读并清除对应提醒，不要求用户逐条点击；打开页面之后才发布的新公告仍应保持未读。
- 公告历史可回看，但新注册用户和迁移前存量用户不应因为账号创建前或功能上线前的历史公告出现首次红点。
- 公告是产品沟通能力，不得写入搜索偏好、图片推荐行为或素材业务事实，也不能替代“提交反馈”。

## 4. 页面布局规范

- 页面内容最大宽度为 `1440px`，桌面端左右留出稳定呼吸空间。
- 页面标题采用统一的 `eyebrow + 标题 + 一句话说明 + 右侧操作` 结构。
- 主要内容使用圆角卡片，但避免每一行都套卡片；卡片只表达一个完整任务或数据区域。
- 后台配置型页面必须清楚区分一级任务和二级控制组：一级任务写名称/说明，二级控制组把相关输入、开关、下拉和保存按钮收在同一个紧凑面板里，避免控件横向散落。
- 列表与卡片间距以 16～24px 为主，表单字段间距以 16～20px 为主。
- 空状态必须说明为什么为空，以及用户下一步可以做什么。

## 5. 上传流程规范

桌面端上传窗口采用双栏结构：

- 左栏：选图、预览、重新选择和移除。
- 右栏：名称、人工筛选信息（渠道、画面风格、是否为场景图）、主要表达卖点、已继承公共话术预览和当前素材独有话术。
- 底栏：固定显示取消、发布和“只选图片即可发布”的状态提示。

交互要求：

- 设计师与管理员的上传入口必须明确区分“上传单张主图”和“批量上传主图”，不能只依赖文件选择器里不显眼的多选能力。
- 单图允许修改名称；多图默认分别使用文件名。
- 批量上传一次选择或拖入多张图片，允许继续追加且自动忽略同一文件；整批只共用使用渠道和卖点关系，不要求逐图填写名称、风格或场景图。不同渠道或卖点的图片应拆成多批。
- 批量上传按顺序自动发布并显示当前文件与整体进度；单张失败不能中断后续图片，已成功图片不得在重试时重复上传，失败图片保留在窗口中供直接重试。
- 多图共享渠道和卖点时必须明确提示；卖点仍为可选人工关系，不因批量能力改成上传硬门槛。
- 渠道、画面风格和是否为场景图均为可选人工属性；界面必须说明它们只服务结果筛选，不触发 AI 分析。场景图使用“是/否/未标注”三态，不能把未标注默认为否。
- “首次 5 条”必须同时说明发布后仍可继续补充。
- 公共话术与当前素材独有话术必须使用独立区域和明确标题，不允许只靠辅助文字区分。
- 同一卖点即使同时存在人工确认和已接受 AI 建议记录，“从卖点继承的公共话术”也只能按卖点展示一张卡；审计来源不能变成界面重复内容。
- 继承卡必须与“已确认关系”中的不同人工卖点一一对应；AI 建议不单独生成继承卡，只有新增人工确认关系后才继承相应公共话术。
- 同文本的不同来源记录在界面只展示一次；来源差异留给审计和数据治理，不增加上传者的阅读负担。
- 素材独有话术的人工新增项和已采纳 AI 项必须进入同一份已确认清单，每条独占一行，不使用横向换行的标签云；AI 待确认候选保持独立分组，采纳后立即移入已确认清单。
- AI 待确认候选在界面上可以审核，但审核前不得进入高优先级素材话术搜索；采纳后刷新搜索索引，拒绝后从搜索语义投影退出。
- AI 卖点建议只展示尚未被人工确认覆盖的不同卖点；同卖点已有人工 accepted 关系时，不再出现“接受/不适用”二次选择，历史重复 pending 由系统自动消解。
- 话术列表超过可视高度时使用内部纵向滚动并保留可见滚动提示；滚动按单条内容对齐，添加入口不得跟随候选列表滚走。
- 已确认话术每行右侧必须提供常驻删除按钮并有可访问名称；删除成功后该行立即退出清单和搜索，不能只允许新增、把移除能力藏在悬停或后台管理页。
- 素材详情的“手动补充确认关系”属于低频操作，默认收起并通过可访问的开关按需展开；已确认关系和未被人工事实覆盖的 AI 待确认建议保持可见。
- “尺寸/渠道延展”弹窗必须明确说明只上传文件和识别尺寸、不运行 AI 分析，并继承主图关系与话术；成功提示不能出现“正在后台分析”。
- 详情页当前打开的横版或竖版始终作为上方主视图，版本卡可双向切换；数据库正式主图在界面中称为“素材组封面”，只表示默认搜索展示身份，避免与当前查看版本混淆。版本卡的删除入口只出现在非封面版本上并始终可见；素材组封面只能通过“替换主图”改变身份，不提供误导性的删除按钮。
- 删除非主图版本必须先确认，并明确说明“只影响当前版本、主图和业务关系不受影响、可从回收站恢复”；确认后该版本立即从当前素材组消失。
- 上传完成后仍可在详情页修改业务筛选信息：使用渠道按当前图片版本维护，画面风格和场景图按整个素材组维护；保存动作必须说明影响范围并刷新当前展示。
- AI 分析说明只保留结果与是否阻塞上传，不展示模型或索引技术细节。
- 素材详情 AI 分析只展示并只生成语义总结以及“画面事实、场景、素材独有搜索表达”三组；OCR、主体、动作、视觉风格、可见产品功能、排除边界和客观内容标签不再分析、存储或进入搜索投影。

## 6. 搜索体验规范

- 搜索框支持卖点、痛点、结果诉求、画面、文案、渠道和尺寸等自然表达。
- 搜索框也支持直接粘贴单张图片的身份码；这仍是同一个搜索入口，身份码命中时优先进行确定性精确查找，不新增第二个“身份码搜索”框。
- 体系筛选放在搜索框下方，标注为可选，不要求业务用户理解内部搜索模式。
- 首页渠道数量超过一行宽度时保持单行横向浏览：鼠标位于渠道栏时，普通滚轮转换为左右滚动；桌面端允许按住鼠标拖动，但只有实际移动超过拖动阈值后才能捕获指针，普通单击必须保持“渠道切换”和“卖点筛选展开”。移动端保留原生触摸滑动。滚动条只在悬停或键盘聚焦时显现，到达横向边界后不得继续截获页面纵向滚动。
- 渠道、画面风格和场景图作为折叠的精细筛选放在体系筛选之后；只有完成搜索后才基于已返回推荐结果启用，不改变原推荐顺序。
- 结果区不重复展示完整查询标题；使用一行数量/已选筛选状态配合“清除搜索”即可。
- 搜索结果展示真实匹配原因、主要/支持卖点和可用版本，不显示内部算法分数。
- 搜索识别到卖点时，在结果顶部显示“本次识别到的卖点”；多个卖点以“全部 + 卖点按钮”呈现，可在当前结果内缩小，不强迫用户先选唯一卖点才能看到图片。
- 结果卡右下角显示“匹配：卖点名称”；多个命中显示首个卖点和 `+N`，悬停可查看完整关系。它是本次查询与素材已确认关系的动态解释，不新增固定图片标签。
- 没有查询级卖点命中时，卡片只可兜底显示素材已有的主要表达关系，并使用“主要”而不是“匹配”，避免误导。
- 每张结果卡提供“就是这张/不相关”双向反馈；反馈只用于搜索运营，不直接修改素材审批或人工关系。
- 整次搜索反馈保留“结果不相关”；素材缺口入口使用“没有合适素材提交需求”，不能用原因不明的“提交需求”或“提交素材需求”。
- 结果卡的尺寸/渠道选择复用标准下拉组件，箭头距右边框 `16px`，文本区域必须为箭头预留空间。
- 图片快捷操作使用图片右侧等间距纵向操作条，不显示中心点、轨道或弧形圆盘；普通业务卡片依次显示“下载、复制身份码、收藏到画板、喜欢、发送到 Agent”，搜索结果可在同一列额外保留“加入/移出多选”。
- 桌面端操作条只在卡片悬停或键盘焦点进入时出现，触摸设备常显；透明外层必须永久透传点击，只有实际可见的操作按钮和尺寸选择器可截获指针，不得遮住当前卡片或瀑布流相邻卡片的详情入口。
- 素材卡和详情页只提供当前图片的一个身份码；不展示素材组码、版本码、二维码、分享链接、数据库 UUID 或真实存储路径。
- 空结果应建议换一种说法、清除体系筛选或补充素材话术。
- 搜索降级时只说明“智能语义搜索响应较慢，已使用基础搜索”和用户可采取的动作；“外部增强”、分支名称、超时预算等技术诊断只在管理员搜索运营页展示。

## 7. 视觉语言

- 基调：黑白暖灰为主，低饱和背景、白色内容面和轻量阴影；蓝色只作为少量信息状态色，不再作为大面积品牌主色。
- 强调只用于主操作、当前导航和明确状态，不用大面积高饱和色争夺注意力。
- 圆角：输入框和按钮约 10～12px，主要卡片和弹窗约 16～30px。
- 标题使用紧凑字距，正文保持 1.5～1.7 行高；辅助文字不得小于可读尺度。
- 图标只帮助识别动作或区域，不替代必要文字。
- 侧边栏图标允许轻量动效：悬停时可有轻微位移、缩放、转动或底光，但不得影响可读性、不得让关键操作只依赖 hover。
- 素材库 Agent 使用项目原创的光球/表情动效；可以参考外部项目的“呼吸、注视、思考、完成、错误”等交互模式，但不得直接使用许可不清或禁止商用的开源角色视觉资产。光球眼睛可以根据指针位置平滑跟随，眨眼和唤醒、思考、完成、异常表情只用于表达助手状态，不承载业务信息。
- 素材库 Agent 的彩色流光只能作为偶发、短时的趣味反馈，沿光球边缘扫过后消失；不得持续彩色发光、遮挡脸部、造成布局抖动或取代黑白暖灰主视觉。思考态可以适度加快频率，但 `prefers-reduced-motion` 时必须关闭。
- 素材库 Agent 闭合态应采用“机器人小球 + 左上角拟人气泡”，气泡可用上下滚动短句提示用户可询问图片、卖点和家长沟通话术，避免只有一个孤立小球。
- 素材库 Agent 的会话切换不得用透明原生下拉伪装；图标、标题、时间和箭头必须在同一个自定义胶囊控件中对齐，焦点态使用黑灰细环而非浏览器默认蓝框。等待模型回复时使用大白框思考态，说明正在处理图片上下文、卖点话术和业务表达，并自动滚到最新内容。

## 8. 文案规则

- 使用业务语言：写“卖点”“素材”“使用渠道”，避免“节点”“标签树”“Provider”等实现词。
- 说明结果：写“发布后可继续添加”，不只写“最多 5 条”。
- 一段辅助文字只解决一个疑问；能用字段标题表达的内容不重复写成长说明。
- 危险操作必须说明不可逆后果，并使用明确确认界面，不依赖模糊提示。
- 加载、空状态、错误和成功反馈必须可区分，不能只靠颜色。

## 9. 响应式与可访问性

- 桌面双栏在窄屏自动变为单栏，主要操作保持在内容之后或固定底栏。
- 所有输入有可访问名称，图标按钮有 `aria-label`。
- 键盘可完成搜索、表单填写、话术添加、弹窗关闭和导航。
- 焦点状态必须清晰；正文和交互元素保持足够对比度。
- 不通过 hover 才展示关键操作，移动端不得依赖鼠标行为。

## 10. 防止体验漂移

以下变化必须先更新本规范和改造总纲：

- 首页新增第二个搜索入口。
- 首次上传增加新的必填业务字段。
- 把首次 5 条话术误写成素材永久总上限。
- 恢复精准/智能模式切换或固定一级—二级标签树。
- 页面重新暴露内部模型分数、Provider 或搜索编排细节。
- 允许版本卡直接删除正式主图，或把非主图删除改成无确认的永久删除。
- 把当前素材组的任一版本重新显示为“相关素材”。
- 把素材需求入口重新缩写为不能解释提交原因的“提交素材需求”。
- 按关系记录数量重复展示同一个卖点的继承公共话术卡。
- 让 AI 建议在没有对应人工确认关系时单独生成继承公共话术卡。
- 把尺寸/渠道延展重新接入 AI 分析队列，或用延展图结果覆盖素材组级关系和话术。
- 把人工新增与已采纳 AI 话术重新拆成两套已确认列表，或恢复横向换行的话术标签云。
- 让 AI 待确认话术与人工已确认话术使用相同的高优先级搜索权重。
- 移除已确认话术的常驻删除入口，或把话术删除改成不保留审核轨迹的物理删除。
- 把 OCR、主体、动作、视觉风格、可见产品功能、排除边界或客观内容标签重新铺回素材详情 AI 分析区。

每轮主要界面改造至少运行前端 TypeScript、ESLint、Vitest、production build，并对首页、上传主流程和受影响后台页面做浏览器走查。
