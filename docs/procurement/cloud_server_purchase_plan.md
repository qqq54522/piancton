# Piancton 图片素材管理与智能搜索系统云服务器资源采购方案

文档版本：V1.0  
编制日期：2026-08-31  
适用项目：Piancton 图片素材管理与智能搜索系统  
文档用途：用于服务器资源采购、预算审批、云厂商选型和上线前资源确认  

## 一、采购背景

Piancton 项目当前已具备 Docker Compose 部署能力，服务结构包括前端 Web、后端 FastAPI、PostgreSQL 数据库、服务器图片持久化存储，以及可选的 Meilisearch 搜索增强服务。项目主要用于内部图片素材上传、审核、版本管理、业务标签确认、图片预览下载、智能搜索、API 中心管理和使用统计。

本次采购的目标不是采购大型分布式架构，而是先完成一套稳定、可备份、可恢复、可扩展的生产起步环境。项目当前阶段建议采用单台通用云服务器承载应用、数据库、搜索增强和图片存储；待真实用户量、图片数量、下载量和 AI 调用量稳定后，再考虑拆分数据库、对象存储、CDN、独立搜索服务或多后端横向扩展。

## 二、项目运行形态

当前项目生产部署形态为：

1. 前端：React/Vite 构建后由 Nginx 提供静态资源和接口反向代理。
2. 后端：FastAPI 服务，负责登录权限、图片上传校验、图片管理、业务关系审核、搜索编排、API 中心和审计日志。
3. 数据库：PostgreSQL，保存用户、权限、素材组、图片版本、业务概念、搜索话术、下载统计和审计日志。
4. 文件存储：服务器持久化图片卷，保存原图和缩略图。
5. 搜索增强：Meilisearch 为可选派生索引，不作为事实数据源；不可用时系统可降级到数据库搜索路径。
6. 外部模型服务：通过 OpenAI-compatible API 或其他中转 API 调用，不需要本机 GPU。

因此，本项目首期采购应重点保障 CPU、内存、磁盘可靠性、公网访问、备份恢复和 HTTPS，不需要购买 GPU 服务器。

## 三、核心诉求

本次采购需要满足以下核心诉求：

1. 支持 Docker Compose 一键部署，降低服务器环境复杂度。
2. 支持 PostgreSQL、后端服务、前端 Nginx、可选 Meilisearch 在同一台服务器稳定运行。
3. 支持图片上传、缩略图生成、预览、下载和回收站恢复。
4. 支持生产 HTTPS 域名访问。
5. 支持数据库和图片文件的定时备份、快照和恢复演练。
6. 支持后续无痛扩展到对象存储、CDN、RDS 和独立搜索服务。
7. 控制首期采购成本，避免过早购买 Kubernetes、GPU、多台服务器或高规格数据库。

## 四、使用场景与预计用量

### 4.1 典型使用场景

1. 设计师或管理员上传主图、延展尺寸图、备选图和修订版本。
2. 系统生成缩略图，并保存原图到服务器持久化卷。
3. 业务负责人确认图片与业务概念之间的主要表达、可支持或不适用关系。
4. 普通业务用户通过一个搜索框检索素材，查看缩略图、预览图并下载原图。
5. 管理员在 API 中心维护模型 API Key、健康检查、调用链路和调度配置。
6. 管理员查看审计日志、使用统计和下载记录。

### 4.2 首期容量假设

首期按内部使用场景估算：

1. 使用人数：5-30 人。
2. 当前素材规模：约 40 个素材组、40 张主图，后续逐步增长。
3. 首期素材规模：500-2,000 张图片以内。
4. 单张原图：通常 1-10MB，极端上传上限为 100MB。
5. 每日访问：50-300 次搜索或素材浏览。
6. 每日下载：10-80 次原图下载。
7. AI 模型推理：主要调用外部模型 API，本机只承担请求编排和结果入库。

## 五、资源采购范围

本次建议采购以下资源：

1. 云服务器：通用型实例，优先 4 核 8GB。
2. 系统盘：40-80GB SSD 或 ESSD。
3. 数据盘：100GB SSD 或 ESSD 起步，用于数据库、图片卷、Meilisearch 数据和备份暂存。
4. 固定公网 IP 或 EIP：用于域名解析、HTTPS 和远程维护。
5. 公网带宽：建议按流量计费，峰值带宽 20Mbps 起步。
6. 域名与 DNS：用于正式访问地址。
7. HTTPS 证书：可使用云厂商免费证书或 Let's Encrypt。
8. 对象存储：用于数据库备份、图片卷备份和长期归档。
9. 云盘快照：用于系统盘和数据盘回滚。
10. 云监控与告警：用于 CPU、内存、磁盘、流量和费用预警。

## 六、推荐配置方案

### 6.1 方案 A：节省试运行版

适用场景：仅限短期测试、验收演示、少量人员访问，不建议作为正式生产长期运行。

配置建议：

1. 云服务器：2 核 4GB。
2. 系统盘：40GB SSD。
3. 数据盘：80GB SSD。
4. 公网带宽：按流量计费，峰值 10Mbps。
5. 搜索增强：默认不启用 Meilisearch，先使用数据库搜索。
6. 备份：每天数据库备份，图片文件每周备份，云盘快照每周一次。

优点：成本低，适合上线前验证。  
缺点：内存余量不足，同时运行 PostgreSQL、后端、前端和 Meilisearch 时容易紧张；图片上传、搜索和 AI 编排并发时稳定性不如推荐方案。

### 6.2 方案 B：推荐生产起步版

适用场景：首期正式上线、内部团队使用、后续逐步增加素材和用户。

配置建议：

1. 云服务器：4 核 8GB，通用型或计算/通用平衡型实例。
2. 系统盘：40-80GB SSD 或 ESSD。
3. 数据盘：100GB SSD 或 ESSD，可后续扩容到 200GB。
4. 公网带宽：按流量计费，峰值 20Mbps 起步。
5. 搜索增强：可启用 Meilisearch；如素材量较少，也可先保持数据库搜索，后续开启。
6. 对象存储：开通同区域 OSS/COS/TOS/BOS，用于备份。
7. 快照：数据盘每日或隔日快照，保留 7-14 天。
8. 监控：CPU、内存、磁盘、流量、费用余额和安全组变更告警。

优点：成本和稳定性平衡较好，足够承载当前项目的生产起步阶段。  
缺点：数据库、应用和文件仍在同一台服务器，极高并发或大规模素材库阶段需要继续拆分。

### 6.3 方案 C：增长稳定版

适用场景：素材达到数千至数万张，下载量明显增加，或公司要求更高可用性和数据安全。

配置建议：

1. 云服务器：8 核 16GB。
2. 系统盘：80GB SSD 或 ESSD。
3. 数据盘：200-500GB SSD 或 ESSD。
4. 公网带宽：按流量计费，峰值 50Mbps；下载量稳定后可评估固定带宽或 CDN。
5. 数据库：可迁移到云 RDS PostgreSQL。
6. 图片存储：可迁移到对象存储，并通过 CDN 加速预览和下载。
7. 搜索服务：Meilisearch 可独立部署，或保留在单机但增加资源。
8. 备份：数据库自动备份、对象存储版本控制、跨区域备份或异地归档。

优点：稳定性、容量和扩展性更好。  
缺点：首期成本明显更高，部署和运维复杂度增加。

## 七、公网带宽与流量说明

云服务器公网流量通常分为入方向和出方向。

1. 入方向流量：用户上传图片、浏览器请求进入服务器，通常不计费或不单独收费。
2. 出方向流量：服务器向用户返回页面、缩略图、预览图和原图下载，通常是主要计费来源。
3. 本项目主要公网成本来自图片预览和原图下载。

建议首期选择“按流量计费 + 峰值 20Mbps”，原因如下：

1. 当前用户量和下载量不确定，固定带宽容易买高或买低。
2. 图片下载具有突发性，峰值 20Mbps 能提供更好的下载体验。
3. 按流量计费便于通过账单观察真实成本，再决定是否切换固定带宽。
4. 后续如下载量稳定且较高，可接入 CDN 或改为固定带宽。

粗略估算：

1. 每日 50 次预览，每次 2MB，约 100MB/日，约 3GB/月。
2. 每日 30 次原图下载，每次 8MB，约 240MB/日，约 7.2GB/月。
3. 加上页面资源、缩略图、后台操作和冗余，首期月出网流量可按 20-100GB 预估。
4. 若未来每日 300 次原图下载，每次 10MB，则约 3GB/日，约 90GB/月。

因此，首期建议设置 300-500GB/月的费用或流量告警，不建议一开始购买过高固定带宽。

## 八、厂商对比

### 8.1 对比维度

本项目云厂商选择主要看以下维度：

1. 云服务器稳定性和规格选择。
2. 国内访问质量和备案便利性。
3. 对象存储、快照、监控、负载均衡、CDN、RDS 的完整度。
4. Docker 部署便利性和镜像拉取稳定性。
5. 后续模型 API、AI 平台或中转服务生态。
6. 价格透明度和公司采购流程匹配度。

### 8.2 阿里云

适合度：最高，建议作为默认首选。

优势：

1. ECS、RDS PostgreSQL、OSS、CDN、SLB、云监控和备案体系成熟。
2. 文档、排障资料和第三方经验丰富，适合正式生产部署。
3. 后续从单机升级到 RDS、OSS、CDN 和负载均衡路径清晰。
4. 中国内地区域选择丰富，适合需要稳定国内访问和 ICP 备案的项目。

注意事项：

1. 活动价格、包年包月价格和按量计费价格差异较大，下单前需以控制台实际价格为准。
2. 需要确认云盘、快照、公网流量和对象存储不是只看服务器裸价。

综合判断：如果公司没有既定云厂商，阿里云是本项目最稳妥的采购选择。

### 8.3 腾讯云

适合度：很高，可作为同等级备选。

优势：

1. CVM、TencentDB for PostgreSQL、COS、CDN、CLB 和云监控能力完整。
2. 价格活动较多，适合预算敏感或公司已有腾讯云账号的情况。
3. 国内访问、备案和对象存储能力能够满足本项目首期上线需求。

注意事项：

1. 需要区分固定公网 IP、EIP、按带宽和按流量计费方式。
2. 如后续迁移到托管数据库或对象存储，需要提前规划内网访问和权限。

综合判断：如果公司已有腾讯云采购体系，腾讯云完全可以满足本项目部署需求。

### 8.4 火山引擎

适合度：高，尤其适合后续接入火山 AI 生态的情况。

优势：

1. 云服务器、对象存储、CDN、负载均衡等基础能力可满足部署需求。
2. 如果后续使用豆包、火山方舟或火山侧模型服务，生态协同更方便。
3. 对 AI 相关项目的产品组合较有吸引力。

注意事项：

1. 企业常规运维经验和第三方资料相对阿里云、腾讯云少一些。
2. 如果只是普通 Web 系统部署，优势不一定明显超过阿里云或腾讯云。

综合判断：如果后续模型服务明确选择火山生态，可以优先考虑火山引擎；否则建议作为备选。

### 8.5 百度智能云

适合度：中等，可满足基础部署，但不作为默认推荐。

优势：

1. BCC 云服务器、BOS 对象存储、CDN 和基础网络资源可满足单机部署。
2. 如果公司已有百度云资源或百度 AI 资源，可降低采购沟通成本。

注意事项：

1. 对于本项目的常规生产部署，综合生态和运维便利性不如阿里云、腾讯云。
2. 如无既有采购原因，不建议作为首选。

综合判断：能用，但不是本项目首期最优选择。

## 九、推荐采购结论

建议选择阿里云作为首期正式部署厂商，采购“推荐生产起步版”。

推荐采购清单：

1. 云厂商：阿里云。
2. 地域：华东 2 上海或华东 1 杭州；如公司或用户主要在华南，也可选择华南 1 深圳。
3. 实例规格：通用型 4 核 8GB。
4. 操作系统：Ubuntu Server 22.04 LTS 或 24.04 LTS。
5. 系统盘：40-80GB ESSD。
6. 数据盘：100GB ESSD，独立挂载，用于 Docker volume 和备份暂存。
7. 公网 IP：固定公网 IP 或 EIP。
8. 公网计费：按流量计费，峰值带宽 20Mbps。
9. 对象存储：OSS 标准存储，首期 100GB 以内。
10. 快照：数据盘自动快照，保留 7-14 天。
11. 安全：安全组仅开放 80、443 和受限来源的 22 端口。
12. 域名：绑定正式业务域名。
13. HTTPS：配置有效证书，生产环境必须启用 HTTPS。
14. 备案：中国内地服务器正式对公网提供服务前需完成 ICP 备案。

## 十、可选增强项

以下资源不建议首期全部购买，可按业务增长逐步启用：

1. RDS PostgreSQL：当数据安全、备份恢复和数据库稳定性要求提高时购买。
2. 对象存储直连图片：当图片数量和下载量明显增加时，将图片从服务器卷迁移到 OSS/COS/TOS/BOS。
3. CDN：当图片预览和下载出网流量明显增加时启用。
4. 负载均衡：当需要多台后端或更规范 HTTPS 入口时启用。
5. Redis：当未来出现多后端共享会话、缓存或容量租约需求时再引入。
6. 独立搜索服务器：当 Meilisearch 索引明显占用单机资源时再拆分。
7. CI/CD：上线流程稳定后接入自动构建和自动部署。

## 十一、安全与网络要求

上线时应满足以下安全要求：

1. 生产域名必须使用 HTTPS。
2. 后端 Cookie 设置 `SESSION_COOKIE_SECURE=true`。
3. `CORS_ORIGINS` 必须设置为最终 HTTPS 域名。
4. 安全组只开放 80、443 和受限管理来源的 22 端口。
5. PostgreSQL 5432 不对公网开放。
6. Meilisearch 7700 不对公网开放。
7. `.env` 中不得使用默认数据库密码。
8. API Key 不写入代码仓库，不出现在截图、聊天记录或公开文档中。
9. 管理员账号上线后立即修改初始密码。
10. 服务器开启登录失败限制、审计日志和基础安全响应头。

## 十二、备份与恢复方案

本项目的核心数据包括 PostgreSQL 数据库和图片持久化卷，两者必须保持同一时间点备份。

建议策略：

1. 数据库备份：每天执行 `pg_dump`，保留 14-30 天。
2. 图片备份：每天增量或全量同步图片卷到对象存储，保留 14-30 天。
3. 云盘快照：数据盘每日或隔日快照，保留 7-14 天。
4. 配置备份：`.env`、部署脚本、Nginx/反向代理配置单独加密保存。
5. 恢复演练：上线前至少完成一次从数据库备份和图片备份恢复到新环境的演练。
6. 备份校验：定期检查备份文件大小、时间戳、恢复可用性和对象存储权限。

重要说明：Meilisearch 是可重建派生索引，不作为主备份对象；主备份应以 PostgreSQL 和图片文件为准。

## 十三、上线验收标准

服务器采购和部署完成后，应按以下标准验收：

1. Docker Engine 和 Docker Compose 已安装。
2. 项目能通过 Docker Compose 正常启动。
3. 前端 Web、后端 API、PostgreSQL 均为健康状态。
4. 如启用 Meilisearch，索引可验证并可重建。
5. Alembic 数据库迁移已升级到最新版本。
6. 管理员账号已创建并修改初始密码。
7. HTTPS 证书有效，HTTP 可正确跳转或代理到 HTTPS。
8. 登录、上传、缩略图、预览、下载、回收站、搜索、权限、审计日志均通过测试。
9. 容器重启后用户、素材、图片和下载计数仍然存在。
10. 数据库和图片备份已配置。
11. 至少完成一次备份恢复演练。
12. 安全组未暴露数据库、搜索服务和内部管理端口。

## 十四、风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 首期服务器规格过低 | 搜索、上传或后台任务变慢 | 推荐 4 核 8GB 起步，保留扩容空间 |
| 图片数据只存本机无备份 | 云盘故障会导致素材丢失 | 每日备份数据库和图片卷到对象存储 |
| 固定带宽买低 | 图片下载体验差 | 首期按流量计费并设置 20Mbps 峰值 |
| 流量费用不可控 | 下载量增长导致费用波动 | 设置流量和费用告警，后续接入 CDN |
| 未备案即使用内地服务器对公网服务 | 域名访问受限或合规风险 | 上线前完成 ICP 备案 |
| 暴露数据库或搜索端口 | 数据泄露或被攻击 | 安全组只开放 80、443、受限 22 |
| API Key 管理不规范 | 外部模型调用被盗用或失控 | 使用 API 中心管理，密钥不入代码仓库 |

## 十五、预算口径

采购预算不应只计算云服务器裸价，还应纳入以下费用：

1. 云服务器实例费用。
2. 系统盘和数据盘费用。
3. 公网出方向流量费用。
4. 云盘快照费用。
5. 对象存储容量和请求费用。
6. 域名和证书费用；免费证书可降低成本。
7. 短信、监控、日志或安全产品费用，如实际启用。
8. 外部模型 API 调用费用。

建议在采购审批中按“服务器基础资源 + 存储备份 + 公网流量 + 模型 API”四类分别列预算，避免后续出现只有服务器可用但缺备份、缺 HTTPS 或缺模型额度的情况。

## 十六、最终建议

本项目当前最合理的采购方案为：

1. 首选阿里云，采购 4 核 8GB 云服务器、40-80GB 系统盘、100GB 数据盘、按流量公网 IP、20Mbps 峰值带宽。
2. 同时开通对象存储和云盘快照，用于数据库和图片备份。
3. 使用正式域名和 HTTPS 证书完成生产访问。
4. 中国内地部署需提前处理 ICP 备案。
5. 首期不购买 GPU、不上 Kubernetes、不拆多台服务器、不提前购买高规格 RDS。
6. 上线后观察 2-4 周真实 CPU、内存、磁盘、搜索延迟、下载流量和模型调用费用，再决定是否升级到增长稳定版。

该方案能够在成本可控的前提下满足项目正式上线、内部使用、图片管理、智能搜索和后续扩展需求，是当前阶段的推荐采购方案。
