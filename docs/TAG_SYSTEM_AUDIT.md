# 标签系统审计与重构基线

更新日期：2026-06-24

> 2026-06-24 备注：本文是改造前审计基线，用于解释为什么要做目录治理和来源拆分。
> 当前代码已经落地权威目录、`assignable` 标签、人工/AI 标签来源拆分、分析批次、
> 可重建搜索索引脚本和精准/智能搜索切换。后续判断真实状态时，以
> `README.md`、`docs/ARCHITECTURE.md`、`docs/SEARCH_MODES_AND_AI.md` 和当前代码为准。
> Meilisearch 仍是可选增强层和派生索引，不是业务事实源。

## 1. 结论

当前项目已经具备六大体系、16 个图片二级卖点标签、开放内容标签、AI 分析和搜索界面，但这些能力尚未形成同一套可追溯的数据协议。

目前至少存在五套相互交叉的分类语言：

1. 六大体系与 16 个二级标签组成的人工标签树；
2. AI 分析后以文本保存的 16 个二级卖点标签；
3. AI 生成的开放内容标签；
4. 上传时人工选择的 `scene` / `function` 图片分类；
5. 文案匹配 Skill 中独立维护的六大体系与 30 个文案卖点。

它们的名字相似，但没有共享稳定 ID、版本、来源和映射关系。因此当前最重要的工作不是继续增加 Prompt，而是先建立唯一目录、跨层映射和版本化的数据边界。

## 2. 当前真实数据

本地数据库 `data/piancton.db` 当前包含：

| 数据 | 数量 |
|---|---:|
| 六大体系根节点 | 6 |
| 二级标签节点 | 16 |
| 图片 | 2（1 张正常、1 张回收站） |
| 人工图片标签关系 | 2 |
| AI 内容标签 | 29 |
| AI 二级标签结果 | 4 |
| 人工图片类型关系 | 2 |

已经发生的偏移：

- 正常图片“动画讲透知识点”的人工标签是“同步校内体系 > 动画精讲”，AI 结果又保存了一份同名文本，同时还给出“同步培养体系 > 万能解法”。
- 回收站图片“学完即测结果反馈”的人工标签直接关联到了根节点“同步伴学体系”，不符合当前只能关联叶子标签的规则。
- 该回收站图片的标题指向“同步校内 / 学完即测”，AI 又同时给出“同步伴学体系 > 学情报告反馈”和“同步校内体系 > 课后小测”，说明人工、标题和 AI 三种口径已经分叉。
- 该旧图片只保存了 9 个英文内容标签和英文摘要，不符合现行“18–22 个中文标签”的规则。新规则不会自动修复旧数据。

这说明本地迁移后的主要风险不是文件丢失，而是规则升级后旧分析结果仍以旧口径留在数据库中。

## 3. 当前链路

```text
六大体系 Python 常量
  -> seed_taxonomy.py
  -> tags 人工标签树
  -> image_tags 人工图片标签

Skill Markdown 中的 16 标签目录
  -> 模型 Prompt
  -> AiService 按另一份 Python 常量校验
  -> image_level2_categories.category_name 文本

开放内容标签 Skill
  -> 模型输出 18–22 个标签
  -> content_tags
  -> 模糊搜索

30 个文案卖点 Skill
  -> 独立 AI 接口
  -> 当前未进入图片搜索与召回链路
```

同一目录目前至少重复维护在：

- `backend/app/domain/taxonomy.py`
- `backend/app/domain/ai_taxonomy.py`
- `skills/classify-secondary-selling-points/RULES.md`
- `skills/match-copy-selling-points/RULES.md`

只要其中一处改名、增删或改变定义，其他位置不会自动同步。

## 4. 主要问题

### 4.1 六大体系不是受保护的主数据

六大体系目前只是普通 `Tag` 数据：

- 没有稳定业务编码；
- 可以在标签管理界面下新增任意根节点和子节点；
- 可以删除整棵体系；
- `is_secondary` 可以被任意设置，与真实层级没有强约束；
- seed 只补充缺失项，不清理或标记非标准项；
- 删除标签会把关联图片一起放入回收站。

因此数据库中的标签树不能被视为六大体系的权威来源。

### 4.2 人工标签和 AI 标签重复保存且无法对齐

人工标签通过 `image_tags.tag_id` 关联标签节点；AI 二级标签则把完整路径拼成字符串，保存在 `category_name`。

AI 结果没有保存：

- 标签 ID；
- 主标签 / 副标签；
- A / B / C 证据等级；
-体系和标签的独立字段；
- 标签目录版本；
- 模型、Prompt 和分析批次。

名称修改后，历史 AI 数据无法可靠迁移；同名标签也无法判断是否属于同一概念。

### 4.3 Skill 是说明文件，不是统一规则源

只有模型 Prompt 会读取部分 Skill。评分、召回和编排 Skill 当前主要是文档，Python 没有执行其中的完整逻辑。

当前 `/api/images/search` 实际只做数据库字符串模糊匹配：

- 没有调用搜索意图理解；
- 没有调用文案卖点匹配；
- 没有执行 Skill 中的分层召回；
- 没有执行 Skill 中的确定性评分公式；
- 没有使用排除标签；
- 没有搜索图片语义总结；
- 没有保存或使用推荐搜索词。

前端保留了语义理解和卖点匹配的展示结构，但后端响应始终是 `fuzzy`。这会造成“页面能力看起来已经存在，真实业务链路却没有接通”的错觉。

### 4.4 搜索字段命名已经失真

- `matched_level1_tags` 实际可能返回二级人工标签。
- `expanded_level1_tags` 在 Skill 中更接近开放内容标签，不是六大体系一级节点。
- `matched_level2_categories` 保存的是完整“体系 > 标签”文本，前端却显示为“匹配大类”。
- 搜索命中内容标签时，返回原因仍可能只是笼统的“标签或内容匹配”。

这些名称继续沿用会让后续开发者错误理解层级。

### 4.5 图片分类存在两套不兼容枚举

上传分类只有：

- `scene`
- `function`

AI 图片类型则是：

- `function`
- `scene_emotion`
- `scene_functional`

AI 的 `image_type` 没有持久化，二者也没有映射协议。

### 4.6 开放内容标签会持续碎片化

内容标签允许开放词汇，但当前缺少：

- 文本标准化；
- 同义词和别名；
- 语言约束的后端验证；
- 最低置信度；
- 重分析版本；
- 人工确认状态；
- 新旧标签兼容策略。

“动画讲解”“动画课程画面”“动画精讲”“动画讲透知识点”可能表达同一概念，却会被当作四个独立搜索词。

### 4.7 关联图片不是真正的关联模型

当前“相关推荐”只查找拥有完全相同人工标签的图片：

- 不使用同体系关系；
- 不使用 AI 二级标签；
- 不使用内容标签相似度；
- 不保存关联原因；
- 不支持系列、前后步骤、同版变体等显式关系。

因此它只是“同标签图片”，不是文档或素材之间的关系网络。

### 4.8 缺少原始依据和版本追溯

仓库中没有最初上传的六大体系原始资料，只保留了整理后的 Skill Markdown。当前代码无法回答：

- 某个标签来自哪份原始文档；
- 为什么属于这个体系；
- 哪次修改改变了定义；
- 哪些图片由哪版规则分析；
- 新规则上线后哪些旧数据需要重跑。

这是本地迁移后最需要补回的治理能力。

## 5. 目标原则

### 5.1 一个唯一目录

六大体系、16 个图片标签和 30 个文案卖点必须来自一份机器可读的权威目录，例如：

```yaml
version: "2026.06"
systems:
  - code: sync_school
    name: 同步校内体系
    image_labels:
      - code: animation_teach
        name: 动画精讲
        aliases: [动画讲透知识点, 动画讲解]
        positive_evidence: [...]
        negative_evidence: [...]
    copy_points:
      - code: material_sync
        name: 教材同步
```

Python 校验、seed、Prompt 和前端展示都应从该目录生成或读取，不再手工复制四份名单。

### 5.2 稳定 ID，不以名称关联

所有业务关联使用稳定 code 或数据库 ID。名称只负责展示，可以修改；历史数据不因改名失联。

### 5.3 分开“真相、判断和观察”

- 体系目录：业务定义的真相；
- 人工打标：人工判断；
- AI 二级标签：模型判断；
- 内容标签：对图片可见内容的观察；
- 搜索扩展：一次查询过程中的临时推导。

这五类数据不能混写到同一字段，也不能互相静默覆盖。

### 5.4 每次 AI 分析可追溯

每次分析至少记录：

- `analysis_run_id`
- `model_provider`
- `model_name`
- `taxonomy_version`
- `prompt_version`
- `created_at`
- `status`
- 原始结构化响应或可审计快照

AI 二级标签还应记录 `label_id`、`role`、`evidence_level`、`confidence` 和 `reason`。

### 5.5 模型负责理解，程序负责约束

模型只能返回目录中的 code；程序负责：

- 目录校验；
- 去重；
- 阈值；
- 主副标签数量；
- 版本记录；
- 评分；
- 召回；
- 数据迁移。

## 6. 建议的数据层

第一阶段不需要一次性重建所有表，可以在现有结构上演进：

### 权威目录

- 为标准标签增加 `code`、`kind`、`locked`、`taxonomy_version`。
- 六大体系和 16 个标准叶子节点设为受保护节点。
- 非标准导航标签与业务标准标签明确区分。

### AI 分析批次

新增 `analysis_runs`，保存模型和规则版本。

### AI 二级标签关系

将 `image_level2_categories.category_name` 改为或迁移到结构化关系：

- `image_id`
- `tag_id`
- `analysis_run_id`
- `role`
- `evidence_level`
- `confidence`
- `reason`

### 内容标签

保留原始内容标签，同时增加可选的标准化字段：

- `raw_name`
- `normalized_name`
- `dimension`
- `language`
- `confidence`
- `analysis_run_id`
- `review_status`

### 文案卖点映射

30 个文案卖点保持独立目录，并通过显式关系映射到：

- 六大体系；
- 16 个图片标签；
- 推荐召回关键词；
- 同义词和反义排除词。

不要假设“30 个文案卖点”和“16 个图片标签”天然一一对应。

## 7. 目标搜索链路

```text
用户查询
  -> 文本标准化
  -> 查询类型判断
  -> 权威目录 code / alias 匹配
  -> 可选模型扩展（输出仍须通过目录校验）
  -> 多路召回
       1. 人工标准标签
       2. AI 标准标签
       3. 标准化内容标签
       4. 标题和语义总结
       5. 文案卖点到图片标签的映射
  -> Python 确定性评分
  -> 排除项扣分
  -> 返回命中证据和版本
```

搜索结果必须解释“为什么命中”，例如：

- 人工标签精准命中“动画精讲”；
- AI 主标签命中“课后小测”；
- 内容标签命中“正确率、学习时长”；
- 由文案卖点“学完即测”映射到图片标签“课后小测”。

## 8. 素材关联策略

默认相关推荐可以按以下信号计算：

1. 相同标准二级标签；
2. 相同体系下的兄弟标签；
3. AI 标签重合；
4. 标准化内容标签重合；
5. 图片类型相近；
6. 标题或摘要语义相近。

如果业务存在“同一活动系列、前后步骤、横竖版变体、原图与成品”等明确关系，再增加显式 `asset_relations` 表，不要全部依赖相似度猜测。

## 9. 分阶段实施

### P0：冻结与备份

- 备份数据库和图片目录；
- 暂停随意增删六大体系节点；
- 找回或重新放入六大体系原始资料；
- 给当前规则标记基线版本。

### P1：建立唯一目录

- 新建机器可读目录；
- 为六大体系、16 个标签、30 个卖点分配稳定 code；
- 建立别名、证据和跨目录映射；
- 用自动测试保证 seed、Python 校验和 Prompt 与目录一致。

### P2：数据结构与迁移

- 增加分析批次和版本字段；
- AI 二级标签由文本迁移到外键；
- 保存主副标签、证据等级和分析来源；
- 标记不符合现行规则的旧分析结果；
- 不自动覆盖人工标签。

### P3：接通搜索

- 先实现不依赖模型的目录匹配、别名、召回和确定性评分；
- 再把搜索意图模型作为可选增强；
- 接入排除词、摘要、标准化内容标签和文案卖点映射；
- 统一后端 schema 与前端展示字段。

### P4：关联与治理

- 重做相关推荐解释；
- 增加人工审核、接受 AI 建议和驳回机制；
- 增加规则版本迁移报告；
- 建立标签变更影响预览，禁止删除标准体系时连带隐藏素材。

## 10. 首批实施范围

下一轮代码调整建议只做 P1，不立即重写搜索：

1. 新建权威目录文件；
2. 给 6 + 16 + 30 个概念分配稳定 code；
3. 明确 30 个文案卖点到 16 个图片标签的映射；
4. 让 `taxonomy.py`、`ai_taxonomy.py`、seed 和模型 Prompt 共同读取该目录；
5. 增加一致性测试，任何名单漂移都让测试失败；
6. 输出当前数据库的迁移预览，但暂不破坏现有数据。

完成 P1 后，再设计数据库 migration。这样可以先固定“什么是正确”，再决定“如何存储和迁移”，避免边改表边继续改变标签定义。
