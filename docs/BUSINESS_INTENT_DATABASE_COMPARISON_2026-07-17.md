## 1. 对比结论

三方的稳定业务骨架一致：六个体系、16 个核心卖点 code 均能一一对应，数据库与静态目录的 16 个当前展示名称完全一致，没有缺失概念、停用概念或人工改名冲突。

真正需要处理的不是重建概念，而是数据库运行态合并规则：

1. **4 个跨体系卖点展示错了主体系。** 数据库关系本身没有错，`core` 与 `support` 都存在；运行时代码取了第一条 active 关系，没有优先 `core`。
2. **14 条共享入口被数据库重新放大成子串强匹配。** 静态目录已经把它们降为 `exact_only_phrases`，但数据库表没有匹配模式字段，旧的 `source_document` 记录仍按普通词条参与长句匹配。
3. **2 条旧话术与本轮统一边界直接冲突。** `universal_method` 中的“一道题会一类题 / 一道题学会一类题”仍是 accepted；本轮已经统一为考试题型迁移 `transfer_practice`。
4. **数据库和静态目录各自仍有少量有价值表达。** 这些表达不能整包互相覆盖，需要按“强意图、共享入口、待确认泛词”分级。

初始对比时数据库中的 433 条卖点话术全部是 `source_document + accepted`，没有人工新增、人工拒绝或人工改写记录。接入完成后仍为 433 条，其中 431 条 accepted；`universal_method` 下两条已被新边界取代的旧种子改为 rejected，concept version 从 1 升为 2。没有批量覆盖或删除话术。

实际接入结果：95 条带目标卖点的评测已经达到 **95/95 均保留正确卖点候选**。5 条纯颜色、版式、场景查询不绑定业务卖点，继续交给画面语义分支。

## 5. 已修复：14 条 `exact_only` 被数据库放大

下列数据库记录本身可以继续 accepted，但运行时必须服从静态校准的 `exact_only` 模式，不能因为 `origin=source_document` 再进入普通子串词组：

| 卖点 | 只应作为整句共享入口的话术 |
|---|---|
| `ai_error_book` | 同类题训练、变式训练 |
| `instant_quiz` | 反馈、掌握情况、正确率 |
| `learning_report` | 反馈、学习反馈、掌握情况、正确率 |
| `photo_guided_learning` | 拍题 |
| `transfer_practice` | 同类题训练、换题也会 |
| `universal_method` | 理解原理、换题也会 |

根因是 `concept_search_phrases` 当前只有 `phrase_type`，没有 `match_mode`；种子脚本也没有把 `exact_only_phrases` 作为一种独立模式写入数据库。

已实施：合并运行时目录时，凡静态目录已声明为 `exact_only` 的标准化词条，从数据库普通 tier 中移除，并继续保留在 exact 集合中。这 14 条数据库记录仍保持 accepted，没有被错误改成 rejected。

长期可选：业务需要完全在后台管理匹配模式时，再为话术增加 `match_mode=substring|exact`，经过迁移和管理端审核后把模式权威迁到数据库。

回滚：短期方案只回滚运行时合并规则，不改 14 条数据库记录。

## 7. 公共话术分级

### 7.1 仅保留为共享入口

这些词不能单独制造明确多卖点，在完整长句中必须看对象、动作、时间尺度、目的和执行主体：

- `AI拍照 / 拍一下`：AI 答疑、拍题精学、极速预习复习、AI 错题本。
- `拍题 / 点拨思路`：当前题分步推导、一般 AI 问答、个人错题归档。
- `同类题训练 / 变式训练`：考试迁移与个人错题复练。
- `理解原理 / 换题也会`：考试题型迁移与长期底层方法。
- `反馈 / 学习反馈 / 正确率 / 掌握情况`：当前一课小测与周期学情报告。
- `老师反馈`：真人过程管理与结构化结果报告。
- `家长省心`：AI 自动规划、真人督学、学情报告。

### 7.2 待业务确认的数据库泛词

数据库还有一批跨卖点重复或过宽表达，当前没有足够依据自动删除：`卡住`、`双重保障`、`复习`、`学习教练`、`家长放心`、`日日清`、`相似题`、`知识点`、`考前`、`能力进阶`、`薄弱点`、`讲解`、`路径`、`迁移`、`进度`、`预习复习`、`高频错题`。

建议先观察真实搜索日志并逐词确认：是 exact 入口、弱辅助词、还是应拒绝。不能因为跨卖点重复就一律删除，多卖点复用本身是允许的。

### 7.3 禁止同步

- 原始脑图中的绿色“待做图/待找图”文字。
- 未核验的专家身份、学校、媒体、证书、奖项、套餐、用户规模和效果数据。
- 证明点原文、长篇解释、示例用户引语。
- Skill 中用于判边界的反例和内部说明。

它们可以留在 Skill 的证明/待核验层，不得批量生成数据库搜索话术。
