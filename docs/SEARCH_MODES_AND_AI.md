# 统一搜索、AI 理解与图片语义分析

状态：Phase 4～6 工程完成。普通业务用户和后端请求均不再存在“精准/智能”模式选择；系统使用一条自动限时、缓存、可降级的搜索编排。

> 当前阶段、数据边界和后续验收以 `docs/IMAGE_SEARCH_REBUILD_MASTER_PLAN.md` 为唯一事实来源。

## 一个搜索入口

业务用户只输入想找的业务点、用户痛点、结果诉求、画面、渠道或尺寸，不需要理解内部召回方式。

六大体系是稳定业务地图和可选快捷筛选：

- 未选择体系时，搜索允许跨体系召回。
- 用户显式选择体系时，该体系才进入硬过滤。
- `search_mode` 只描述本次实际服务来源，例如数据库模糊路径或 Meilisearch，不是用户可选模式。

搜索完成后还可以按设计师人工维护的渠道、画面风格和“是否为场景图”继续缩小当前推荐结果。这是稳定顺序的精确二次筛选，不会再次调用 AI，也不会改变卖点识别、素材召回或 Reranker 排序；未标注图片不会被当成“非场景图”。

## 在线搜索编排

页面过去显示的“智能语义”不是用户可选择的另一种搜索模式，而是以下可选内部增强的统称：生成式模型理解模糊长句、Embedding 扩大相似语义召回、Meilisearch 扩大关键词召回、Reranker 对较多候选重新排序。它们不能替代六体系 Skill、本地卖点目录、公共话术和人工确认素材关系。

在线链路按配置启动以下来源：

```text
模型第一层判体系 ─> 只加载候选体系 ─> 模型第二层判卖点 ─> accepted 关系素材 ─> 素材独有话术选图
本地固定目录 ───────────────────────────────┘（封闭 code 约束与模型失败兜底）
数据库图片/素材短语 ─┐
Meilisearch 关键词 ───┼─> 全局候选池 ─> 仅在待消歧、纯画面或无可靠卖点时兜底
Embedding 画面语义 ──┘
```

职责边界：

- `SearchService` 只装配依赖并提供同步/异步门面。
- `AsyncSearchOrchestrator` 只串联流水线。
- `SearchExternalBranches` 管理外部分支、缓存和主会话水合。
- `SearchRerankCoordinator` 管理总截止内唯一一次重排。
- 外部分支先返回轻量候选 ID 或向量，不在线程间共享 SQLAlchemy Session。

默认时间预算：

| 环节 | 当前预算 |
|---|---:|
| 可选召回/重排总截止 | 2.5 秒；不包含渐进式查询理解等待 |
| Meilisearch | 0.2 秒；高置信本地卖点查询跳过 |
| Embedding | 1.8 秒；高置信本地概念查询跳过 |
| 第一层体系路由 | 8 秒；只判断六大体系 |
| 第二层卖点判断 | 20 秒；只读取候选体系卖点摘要与启用目录 |
| 第三层证明点判断 | 20 秒；只读取已命中卖点的直属证明点 |
| Top 20 Reranker | 1.4 秒，且受剩余总截止约束；可信卖点仅 1～2 组候选时跳过 |

D152 后，GPT-5.5 查询理解正式采用严格三级串行链：体系、卖点、证明点分别使用独立 Prompt、结构约束和 `8s/20s/20s` 预算。第二层不再加载证明点或证据表达点目录，第三层只接收第二层已确认卖点的直属候选，因此单次上下文更短、职责更集中。自然语言在线搜索每次询问模型，本地强证据继续用于阻止错误模型结果覆盖人工确认边界。当前三级链总耗时仍需用真实查询完成端到端 P95 验收，预算上限不能描述成目标延迟或已稳定达标。查询 Embedding、Reranker 和 Meilisearch 仍是可选技术增强，不能突破卖点主通道。

## 降级规则

- Meilisearch 不可用：继续数据库概念/短语召回和其他可用分支。
- Embedding 不可用：继续数据库与 Meilisearch。
- 查询理解模型不可用、结构无效或超过 15 秒：继续本地固定目录理解和已有召回，并记录真实降级。
- 可信卖点主通道有素材：返回该通道，不混入卖点外的标题或话术巧合命中。
- 可信卖点主通道无已确认素材：返回空结果，明确暴露素材缺口；外部分支不能拿无关库存补位。
- 待消歧、纯画面或无可靠卖点：允许使用全局图片话术、标题和画面语义候选兜底。
- Reranker 不可用或超时：使用本地融合分数排序。
- Reranker 开始前若剩余总时间已经不足以覆盖完整分支预算：直接保留本地排序，不启动一次注定超时的调用。
- 所有外部能力不可用：数据库路径仍必须返回可用结果。
- 后台诊断继续记录任一外部分支失败；普通页面只有在本次查询没有可靠卖点、确实依赖外部语义召回时才显示降级。可信卖点主通道已经完整返回时，不因可选分支失败误报“结果可能不完整”。

生成式“图片摘要裁判”已经退出在线链路；候选融合后最多调用一次 Reranker。

## 上传阶段的 AI

设计师首次上传只要求图片文件，标题可以由文件名生成。业务概念、渠道、人工画面风格、是否为场景图、素材独有搜索语和延展尺寸均为可选。渠道保存在具体图片版本，风格与场景图状态由素材组共享；三项人工筛选属性不会从 AI 结果自动回填。

模型 Provider 已配置时，上传后可以异步执行：

- 一段可检索的语义总结；
- Semantic Profile V3 的画面事实、场景和素材独有搜索表达；
- 可审核的业务概念关系建议；
- Embedding 与派生搜索索引刷新。

OCR、主体、动作、视觉风格、可见产品功能、排除边界和客观 `content_tags` 已退出分析协议。模型即使误返回这些旧字段，也会在 normalizer 边界被丢弃，不写入新分析结果或搜索投影。

Provider 未配置或分析失败不影响图片上传、预览、下载和人工关系维护。

尺寸/渠道延展不进入上述流程：它只上传文件、生成缩略图并识别尺寸，直接继承素材组已有业务关系和搜索话术。完整 AI 分析只服务正式主图或确有独立画面语义的非延展版本；任何非主图分析都不能覆盖素材组级 AI 候选。

## 客观语义与业务事实分离

图片客观语义保存在 Semantic Profile V3，只包含画面事实、场景和素材独有搜索表达。AI 对业务含义的判断只能写成素材概念关系建议：

- `origin=ai`；
- `review_status=pending`；
- 关系为 `expresses` 或 `supports`；
- 必须给出证据与相邻概念排除边界。

负责人确认后形成 `origin=manual`、`review_status=accepted` 的业务事实。AI 重跑不得覆盖人工确认或人工拒绝结果；同一卖点已有人工 accepted 关系时，对应 AI pending 建议会自动软拒绝，后续分析也不再重新生成该待审核项。已接受 AI 记录仍可保留为审计来源，但不会再次要求用户审核。

## 业务概念与搜索语言

- 六大体系稳定节点位于 `tags`。
- 可变化业务概念位于 `business_concepts`。
- 通用业务话术位于 `concept_search_phrases`，在概念层复用。
- 图片独有画面或场景表达位于 `asset_search_phrases`。
- 图片与概念的主要表达、支持或排除关系位于 `asset_concept_links`。

当前 16 个概念和初始表达由 taxonomy 源文件幂等初始化。概念层是运行事实来源，D027 已按 D053 落地：本地意图词包、AI 查询理解 Prompt 和图片分析封闭目录校验都在运行时由数据库当前启用卖点合成，改名、新增、停用和拒绝话术即时生效；静态 taxonomy 与意图文件只提供初始种子、证据边界和数据库不可用时的兜底。种子脚本只补空缺，不覆盖人工维护字段。

## 查询状态与否定表达

查询理解输出封闭的 `query_type` 枚举：

- `business_intent_search`：明确单卖点，进入该卖点主通道；
- `multi_business_intent_search`：一句话内每个卖点都有独立证据，才算真多卖点，并行打开主通道，前端提示“本次需求同时涉及”；显式“既要/还要/同时”等连接词加两个以上高置信数据库概念表达也可在模型超时时确认该状态；
- `exploratory_business_intent_search`：共享入口词（如“AI拍照”“家长省心”）命中多个卖点且证据完全相同，召回同多卖点合并，但前端提示“你可能在找”，不伪装成已确认多卖点；
- `ambiguous_business_intent_search`：候选存在但无法区分相邻卖点，不执行硬路由，保留全局兜底；
- `visual_scene_search` / `no_reliable_intent_search`：按画面语义全局召回。

显式否定表达（“不需要真人老师”“不要课后小测”）会把对应卖点写入 `excluded_concepts`：该卖点不参与召回，主要表达它的素材在路由层被过滤。否定判定保持保守，只处理否定词紧邻卖点词条且该卖点没有其他正向证据的情况；词库中自带“不…”的正向话术（如“不直接给答案”）不受影响。模型返回的自造 `query_type` 在 AI 边界层映射进封闭枚举，未知多候选一律按待消歧处理。

## 搜索结果与反馈

搜索按素材组返回：

- 同一主视觉的横版、竖版和渠道延展只占一张结果卡；
- 用户在卡片内选择需要的尺寸或渠道；
- 匹配原因来自真实命中链路，不由模型自由编写；
- 结果顶部按查询状态展示卖点：单卖点/真多卖点为“本次识别到的卖点/本次需求同时涉及”，探索型为“你可能在找”，可在当前结果内缩小；未消歧候选不伪装成多个已识别卖点；
- 卡片右下角展示本次查询命中的卖点；该标签由查询候选与素材已确认关系动态求交，不是新建的图片固定标签；
- 单结果“就是这张/不相关”反馈都记录查询、图片和素材组，只用于搜索优化，不修改发布审批或人工概念关系。

当前分层搜索顺序：

1. 查询理解模型先只判断体系，再只在候选体系的卖点公共话术与边界内确定一个可信卖点，或确认一句话确实同时表达多个卖点；本地固定目录用于结构约束与失败兜底；
2. 只在这些卖点 accepted `expresses/supports` 素材内，用人工新增或已采纳 AI 的素材独有话术承担具体图片主筛选；话术同时与原句、标准化意图、可信扩展词和卖点名比较；
3. 同卖点已有 `expresses` 直接素材时，只有 `supports` 的证明图必须命中 accepted 图片话术，或被查询明确点名标题、语义总结、V3 画面事实/场景才进入；没有 `expresses` 时允许 accepted `supports` 保底，随后再由关系角色、基础召回分和一次 Reranker 补充排序；
4. 主通道无素材时返回空结果；只有意图待消歧、纯画面或无可靠卖点时，才使用标题、全局图片话术、语义总结、画面事实、场景和 Embedding 兜底；
5. AI 待审核素材表达与待审核概念不进入高优先级主通道。

数据库召回用自动化测试固定公共话术 `0.95`、已确认素材独有话术 `0.90` 的基础权重；Meilisearch 把已确认卖点名称、公共话术和素材独有话术排在标题之前，但在线编排还会施加上述卖点主通道边界。AI 待审核素材话术不进入高优先级入口，只将原始 AI 语义表达用于低优先级 Semantic Profile、Embedding 和 Reranker；拒绝或由维护者删除后从直接召回与语义投影一并排除。Embedding 用于扩大模糊语义候选，Reranker 只在主通道或兜底通道内部重排，不能跨越体系硬过滤、人工排除关系或卖点主通道边界。
