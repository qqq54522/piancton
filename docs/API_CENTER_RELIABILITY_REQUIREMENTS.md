# API 中心可靠性需求基线

版本：1.5
日期：2026-08-29
状态：P0 分步收口中；已实现单 backend 后台维护巡检和日志保留清理

## 1. 目标

API 中心是全项目模型调用的唯一控制面，不只是密钥列表。它必须让管理员在不修改业务代码、不重启服务的前提下完成 API 入库、验证、启停、任务调度、失败切换、负载分散和调用追踪。

可靠性的最终判断不是“页面上有配置”，而是以下闭环同时成立：

1. 库存知道有哪些 API，以及管理员是否允许使用。
2. 探测知道 API 当前能否完成真实调用，以及支持哪些能力。
3. 调度知道某个业务任务应该从哪些健康候选中选择。
4. 运行时在单个候选失败后继续其他候选，不把中转站异常扩散为业务失败。
5. 日志能够证明实际调用了谁、为什么切换以及整次业务请求是否成功。

## 2. 非目标

- 当前阶段只实现单 backend 后台维护巡检；多服务器共享调度、共享容量租约和集群级巡检继续延期。
- API 中心不决定搜索业务事实、卖点、证明点、素材准入或排序。
- 健康检查不承诺外部中转站永远可用，只负责给出可复现的当前判断和自动恢复路径。
- 当前单 backend 部署只实现进程内调度快照、容量账本和短 TTL 指标缓存；多进程或多服务器共享容量租约继续延期，不能把进程内状态描述为集群状态。

## 3. 核心原则

### 3.1 唯一事实来源

- 数据库 API 中心是运行时唯一库存来源；`.env` 只允许首次空库迁移。
- 新增、更新、停用和删除在保存后立即生效，不要求重启。
- 删除最后一个 API 后不得从环境变量自动恢复。

### 3.2 管理状态与运行状态分离

- 管理状态只表达管理员的 `启用/停用` 意图。
- 健康、超时、限流和调用失败只进入运行状态与日志，不得擅自停用 API。
- 自动任务可以按健康降级候选；人工指定任务仍按显式主备尝试，除非管理员停用或删除。

### 3.3 自动化优先

- 管理员不手填 temperature、并发容量和等待秒数等需要实验才能知道的技术参数。
- 系统通过真实最小探针和运行数据自动校准；页面只展示结果、原因和必要的业务开关。
- 错误提示必须说明系统已经做了什么和下一步会做什么，不能把内部参数猜测转嫁给管理员。

### 3.4 成功优先且可解释

- 自动模式先保证候选健康和任务兼容，再做 Provider 级与 Key 级负载均衡。
- 单个 API 失败、超时、限流、返回非法结构或达到容量上限后，应在任务预算内继续其他候选。
- 每次候选选择、失败和切换都必须进入同一请求链路，不能只记录最终一个结果。
- 同一中转站下多个 Key 的异常必须能被聚合展示；系统可以建议整站处理，但不得在未得到管理员明确操作前擅自停用整站。

## 4. 故障分类与规定行为

| 故障类型 | 稳定错误码 | 系统规定行为 | 是否自动重试 |
|---|---|---|---|
| 地址格式错误 | `invalid_base_url` | 保存前拒绝，并指出正确地址格式 | 否 |
| 协议/Provider 不支持 | `unsupported_provider_type` | 保存前拒绝，不能显示保存成功后在运行时仍按另一协议调用 | 否 |
| DNS、TLS、连接失败 | `connection_failed` | 健康探测同轮再试一次；运行调度切换候选 | 是，有限次 |
| 建连超时 | `connection_timeout` | 同上，并与响应等待超时分开记录 | 是，有限次 |
| 密钥无效或无权限 | `authentication_failed` | 明确标记鉴权问题，不重复消耗调用 | 否 |
| 模型不存在或无权调用 | `model_not_found` | 明确显示配置的模型名与 Provider，不误报网络问题 | 否 |
| 限流 | `rate_limited` | 当前请求切换候选；Provider 进入短期运行退避但不改变管理员启停 | 是，有限次 |
| 中转站 5xx | `upstream_unavailable` | 当前请求切换候选；健康探测同轮再试一次 | 是，有限次 |
| 响应等待未完成 | `response_timeout` | 健康检查使用独立系统窗口；运行调度在任务预算内切换候选 | 是，有限次 |
| 返回非 JSON | `invalid_json_response` | 视为本次候选不兼容并切换，保留安全摘要 | 可换候选 |
| 返回结构缺字段 | `invalid_response_shape` | 视为任务契约失败并切换，不能把它记成网络失败 | 可换候选 |
| temperature 不兼容 | `temperature_not_supported` / `temperature_value_unsupported` | 自动尝试兼容值或完全不发送参数 | 仅参数候选 |
| `response_format` 不兼容 | `response_format_unsupported` | 自动降级为不发送该参数并继续验证 JSON | 仅参数兼容 |
| 任务能力不兼容 | `task_capability_unsupported` | 不进入该任务自动候选，但仍可用于已验证兼容的其他任务 | 否 |
| 容量已满 | `capacity_saturated` | 不发起调用，立即选择其他候选或在任务预算内等待 | 动态选择 |
| 请求取消 | `request_cancelled` | 停止等待和后续 fallback，不误报地址或网络异常 | 否 |
| 页面等待结束 | `client_wait_timeout` | 提示刷新并查看后台链路；不能改变 API 健康状态 | 否 |

## 6. 上线前 P0 收口清单

以下事项优先于继续增加 API 中心功能：

1. 后端原子化执行“探测通过后入库”，禁止绕过前端直接保存未验证 API。（已完成）
2. Provider 类型与地址契约收口，避免保存成功后才发现协议或地址拼接错误。（已完成）
3. 建立任务能力探针，至少区分文本 JSON 与图片输入能力。（已完成）
4. 批量健康巡检按 Provider 主机分组限流，避免同站多个 Key 相互制造假异常。（已完成）
5. 明确并验证候选失败后的遍历与任务预算策略，不能让首个慢 API 吃完全部 fallback 时间。（已完成）
6. 修正“系统估算并发容量”的实现或页面口径，二者必须一致。（已完成当前口径）
7. 保持删除、停用、自动候选、人工主备和任务屏蔽的组合回归测试。
8. 单 backend 调度热路径使用请求级配置快照和短 TTL 指标缓存，为未来 100～200 个 API 保留演进空间。（已完成当前口径）
9. API 库存阻止同站同模型同 Key 重复保存，并对凭据生命周期操作写入非敏感审计。（已完成）
10. 调用链路日志持久化稳定错误码，并提供分页筛选入口，避免只能观察最近 100 条摘要。（已完成）
11. 错误码统一进入故障分类目录，健康检查和调用日志返回同一套系统动作与管理员建议。（已完成）
12. 单 backend 后台维护按配置自动抽检到期 API 并清理过期调用链路/健康快照，页面展示最近状态和手动立即维护入口。（已完成当前口径）

## 7. 场景验收矩阵

| 场景 | 必须结果 |
|---|---|
| 新 API 密钥错误 | 后端拒绝入库，显示鉴权错误 |
| 同站同模型同 Key 重复新增 | 后端以 `api_credential_duplicate` 拒绝，不再次消耗探针调用 |
| 同站不同 Key 或同 Key 不同模型 | 允许保存为不同合法库存 |
| 模型名错误 | 后端拒绝入库，显示模型不存在，不误报网络 |
| 地址填到完整 completions 路径 | 自动规范化或保存前明确拒绝 |
| temperature 不支持 | 自动改为兼容值或不发送参数 |
| API 25 秒才返回健康探针 | 健康检查通过并自动校准，不要求管理员调秒数 |
| 首次连接失败、第二次成功 | 同轮自动恢复为健康，并保留真实 attempts |
| 同一中转站有四个 Key | 批量巡检按站限流，不能四个同时压上游 |
| 两个中转站使用同一模型 | 自动调度跨 Provider 轮转，再在站内分 Key |
| 某个中转站多个 Key 最近集中超时 | API 管理页聚合显示该站为观察或建议处理，管理员可一键停用该站全部 API；系统不得擅自停用 |
| 当前候选 429/5xx/超时 | 在任务预算内切换其他健康候选 |
| 模型返回非法 JSON/字段缺失 | 记录契约错误并切换候选，不误报网络 |
| 文本探针通过但图片任务不支持 | 不进入图片任务自动候选；页面 API 列表显示图片输入能力为不匹配或未检测 |
| 相同搜索重复执行 | 每次产生新的模型调用和独立请求链路 |
| 管理员排查调用异常 | 可按任务、状态、中转站/API、请求 ID、搜索关键词或错误码筛选分页查看调用链路 |
| 同一错误码反复出现 | 页面显示统一故障类别、严重度、可重试性、系统动作和管理员建议，不靠临时中文摘要判断 |
| 管理员不打开 API 中心页面 | 单 backend 后台 worker 仍按配置周期抽检到期启用 API，并清理超过保留期的调用链路和健康快照 |
| API 停用 | 自动任务立即不再选择；人工配置保留但不可运行 |
| API 删除 | 库存、槽位引用、屏蔽引用和容量状态全部清理，不从 `.env` 恢复 |
| API 新增、修改、停用、删除或整站停用 | 后台审计记录管理员、request_id 和非敏感变更摘要，不出现完整 Key 或 Key preview |
| 页面等待结束但后端仍运行 | 页面不修改健康结论，引导查看后台链路 |
| 查看任何日志和响应 | 不出现完整密钥、Prompt、图片或私聊正文 |

## 8. 完成定义

API 中心可靠性阶段只有在以下条件全部满足后才能标记完成：

- P0 需求均有自动化测试，且至少一次 Docker 真实中转站验收通过。
- 每种故障都能稳定归类，页面文案与后端错误码一致。
- 配置保存后无需重启，运行时行为与页面状态一致。
- 自动调度的候选准入、负载均衡、失败切换和日志能够由同一请求链证明。
- 文档、OpenAPI、前端类型、数据库迁移和当前运行代码没有漂移。
