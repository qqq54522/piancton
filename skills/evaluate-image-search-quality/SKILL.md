# 评测图片搜索质量

使用运行数据库中已发布、人工 `accepted` 的 `expresses/supports/excludes` 关系动态生成金标准。图片标题、搜索解释、AI pending 建议和模型自评都不能代替金标准。

## 运行流程

1. 完整阅读总纲当前决策、`taxonomy/search_eval_cases.json`、`backend/app/domain/search_eval.py` 和 `backend/scripts/run_search_eval.py`。
2. 先运行不外发数据的本地链路评测，记录用例数、数据库绑定覆盖、意图、Top 3、Top 5、查询类型、空结果、越界、人工 excludes、P50/P95和分支状态。
3. 只有用户明确同意把评测业务语句和相关 Prompt 发给指定 Provider 时，才运行 `--with-ai`。授权不自动延续到新的数据集或新的外部服务。
4. 批量模型评测必须记录每级 Provider、耗时、错误、超时、降级和最终采用来源；不得用单条成功代表全量稳定。
5. 将失败按“意图错误、人工关系缺口、第三层图片筛选、外部超时、评测金标准问题”分类，先固化最小回归再修改代码。
6. 修改后使用同一数据集重跑；报告本地与AI链路的独立结果，不用一个总体数字掩盖降级。

## 保护边界

- 评测默认只读，不修改生产素材、人工关系、话术、卖点目录或搜索反馈。
- 外部模型的 `ok` 只表示返回合法结构；业务正确性必须与动态金标准比较。
- 纯画面用例没有画面级金标准时标记 `partial`，不能计入业务卖点准确率冒充完成。
- 评测结果只用于受控改进，不自动训练模型或写回 accepted 数据。

## 验收基线

以总纲最新记录为准。当前本地95条业务用例基线为意图 `95/95`、Top 3 `94/95`、Top 5 `94/95`；新的整理和重构不得降低该结果。
