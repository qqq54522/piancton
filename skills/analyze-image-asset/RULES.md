# 图片素材分析运行时规则

用途：让视觉模型输出稳定、可校验的图片语义数据和可审核业务概念关系建议。

## 输出协议

只返回以下 JSON：

```json
{
  "image_summary": "一段简洁、客观的中文画面总结，只描述可见内容",
  "semantic_profile": {
    "schema_version": 3,
    "visual_facts": ["用完整短句总结图中真实可见的关键事实"],
    "scenes": ["用完整短语概括这张素材适用的真实场景"],
    "asset_search_phrases": ["仅对这张素材成立的画面、文案或使用场景搜索表达"]
  },
  "concept_suggestions": [
    {
      "concept_code": "当前启用业务概念的稳定 code",
      "system_name": "六大体系中的相关体系",
      "concept_name": "当前启用目录中的卖点名称",
      "confidence": 0.0,
      "evidence_level": "A | B | C",
      "relation_role": "expresses | supports",
      "reason": "说明画面证据以及为什么不是相邻易混卖点"
    }
  ]
}
```

## 画面语义

- 所有字段使用中文，只描述图片真实可见内容，不补充图片外的产品能力、营销结论、效果、客户、学校或数据。
- `image_summary` 必须可检索，优先概括可见人物、学习页面、报告、题目、课程规划、交互和版式证据。
- `visual_facts` 返回 2～6 条不重复事实；合并主体、文字、结构和动作，不拆成固定词标签。
- `scenes` 返回 0～4 条真实使用或展示场景；证据不足时允许为空。
- `asset_search_phrases` 返回 0～8 条只对当前素材成立的自然表达；通用卖点语言属于概念层，不在单图重复。
- 不输出 OCR、主体、动作、视觉风格、可见功能、排除边界、固定二级标签、`content_tags` 或推荐关键词等旧字段。

## 业务概念建议

- 只能从 Prompt 附带的当前启用概念目录选择稳定 code，不得创造卖点或修改体系归属。
- 最多一个 `expresses` 和两个 `supports`；没有可靠画面证据时允许返回空数组。
- A 表示直接功能或界面证据，B 表示行为/使用场景证据，C 表示结果或情绪证据；单独 C 级证据不能支持 `expresses`。
- `reason` 必须同时解释正向证据和相邻卖点排除边界，不能只说“语义相关”。
- 输出只是待负责人审核的建议，不得宣称已确认、已发布或已进入搜索金标准。
