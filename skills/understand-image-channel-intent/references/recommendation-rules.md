# 渠道推荐解释规则

推荐解释面向业务方，必须回答“为什么这张图适合我说的渠道”，不要暴露模型分数、内部标签或后端流程。

## 通用结构

```text
推荐用于{渠道}：{渠道规则}。这张图/这类结果{图片或需求事实}，所以更适合{具体使用位置}。
```

## 渠道规则

- `PPT`：PPT 用于讲解和汇报，需要画面结构清楚、层级完整、能承接讲述节奏。
- `品牌手册`：品牌手册用于沉淀标准表达，需要口径稳定、画面规范、信息不依赖临时活动语境。
- `手机端大图`：手机端大图适合首屏、活动页或重点位置，需要主体突出、卖点直接、能快速建立认知。
- `手机端小图`：手机端小图常出现在列表、入口或推荐位，屏幕空间小，用户识别时间很短，通常只适合单一重点。
- `官网大图`：官网大图承担首屏信任和产品定位，需要视觉完成度高、场景完整、卖点明确。
- `官网小图`：官网小图常用于模块、列表和辅助说明，需要缩小后仍能看清主体和核心信息。

## 不能做的事

- 不要说“系统识别到”“模型认为”“匹配分数”。
- 不要把渠道推荐写成业务事实核验结论。
- 不要在只识别到家族时强行说用户一定需要大图或小图。
- 不要用固定套话代替需求事实；推荐语至少应包含用户原话里的一个需求要点或渠道词。
