# 使用渠道意图识别

把自然语言需求翻译为“使用渠道 + 尺寸语境 + 场景图倾向 + 推荐解释”。本 Skill 只判断素材将被用在哪里、以什么展示形态出现，不判断用户想表达哪个业务卖点。

## 使用顺序

1. 保留用户原话，先识别渠道家族：`PPT`、`品牌手册`、`手机端`、`官网` 或 `unknown`；“朋友圈、微信朋友圈、社媒、社交平台、运营长图、活动长图、长图”按手机端使用语境处理。
2. 再识别尺寸语境：`large`、`small` 或 `unspecified`。
3. 只有用户明确说到大图、小图、首屏、banner、主视觉、列表、入口、缩略图、小卡片等词时，才输出具体子渠道。
4. 用户只说“手机端”“移动端”“App 里用”时，不强判 `手机端大图` 或 `手机端小图`；候选应同时包含两者。
5. 用户只说“官网”“网站”“落地页”时，不强判 `官网大图` 或 `官网小图`；候选应同时包含两者。
6. 用户说“发朋友圈/朋友圈素材”时，默认偏 `手机端大图`；若同时说“九宫格、列表、入口、小图、缩略图、信息流”等，则偏 `手机端小图`。
7. 用户说“运营长图/活动长图/长图”但没说模块大小时，同时保留 `手机端大图`、`手机端小图`；说“大模块/主模块/重点模块”时偏 `手机端大图`，说“小模块/次级模块/辅助模块”时偏 `手机端小图`。
8. 用户没有提及任何渠道时，默认普通搜索结果只保留 `手机端大图`、`手机端小图`；用户明确说 PPT、品牌手册、官网或其他渠道时，以明确渠道覆盖默认。
9. 单独识别是否偏场景图：用户说“真实使用、场景、人物在用、家长看到、老师使用、孩子操作”等，输出 `scenePreference=scene`；用户说“图标、界面截图、功能图、功能截图、功能卡片、纯排版”等，输出 `non_scene`；无法判断输出 `unspecified`。
10. 输出推荐理由时必须同时说明渠道规则和图片/需求事实，不要输出内部模型、体系、分数或算法解释。

## 输出 Schema

详见 `references/output-schema.json`。核心字段：

- `channelFamily`：渠道家族。
- `channelSize`：尺寸语境。
- `exactChannel`：只有明确到 6 个固定渠道之一时填写。
- `candidateChannels`：可用于结果后二次筛选的候选渠道。
- `scenePreference`：是否偏场景图。
- `confidence`：`high`、`medium`、`low`。
- `evidence`：触发判断的原文词。
- `recommendation`：给业务方看的推荐解释。

## 判断边界

- 渠道意图与卖点意图并行：一句“手机端能够体现家长看到学习结果”应同时交给卖点 Skill 和本 Skill，前者识别“学习报告反馈/学习结果可见”，后者识别“手机端”。
- 渠道只用于搜索结果后的推荐、解释和二次收窄，不进入卖点主通道，不改变人工 accepted 关系边界。
- 没有渠道证据时不猜测；只根据素材标题或卖点名称猜渠道会造成误筛。
- 新增渠道时优先扩展 `references/channel-taxonomy.md` 和运行时解析规则，再进入上传/筛选选项。

- `references/recommendation-rules.md`：面向业务方的推荐解释规则。
